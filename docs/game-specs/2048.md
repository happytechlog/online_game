# 2048 Specification

## Scope

2048 is a single-player browser puzzle played on a fixed 4×4 board. It follows
the original rules and excludes undo, configurable board sizes, alternate tile
sets, accounts, online leaderboards, remote play, and external services.

## Rules

- A new game begins with two tiles in distinct random cells.
- Each starting or spawned tile is 2 with 90% probability or 4 with 10%
  probability.
- A move slides every tile as far as possible in the chosen direction.
- When two equal tiles collide, they merge into one tile worth their sum.
- A tile created by a merge cannot merge again during the same move.
- Multiple lines are resolved independently and in the direction of movement.
- The score increases by the value of every tile created by a merge.
- A move that changes the board spawns exactly one new tile in an empty cell.
- A move that does not change the board does not spawn a tile or change score.
- Creating a 2048 tile triggers the win state once. The player may continue the
  same game afterward.
- The game ends when the board is full and no horizontal or vertical pair of
  adjacent tiles has the same value.

The engine is immutable and independent of React, browser APIs, storage,
timers, and ambient randomness. Tile placement and value generation are
injected so rule tests remain deterministic.

## Controls and interface

Players can move with the arrow keys, W/A/S/D, or a horizontal or vertical
touch swipe. Equivalent inputs must produce the same engine action. Input is
ignored while a modal win or game-over decision is active.

The interface includes the board, current score, best score, new-game control,
short control instructions, a one-time 2048 win message with a continue action,
and a game-over message with a new-game action. It does not include undo.

Starting a new game resets the board and current score but never lowers the
stored best score. Reaching 2048 and choosing continue preserves the current
board and score.

## Persistence

Use versioned keys such as `online-games:2048:save:v1` and
`online-games:2048:best:v1`. The saved game includes the 4×4 board, current
score, whether the win message has been shown, whether the player chose to
continue, and the schema version.

Validate the payload version, board dimensions, tile values, score, and boolean
flags before restoration. Every nonempty tile must be a power of two of at
least 2. Invalid JSON, unsupported versions, impossible values, unavailable
storage, and write failures must fall back safely without interrupting play.
The best score is never restored below the valid current score.

## Site integration and content

The public route is `/games/2048`. It has unique bilingual metadata, one H1,
ordinary HTML guidance, controls, rules, and FAQ content. The canonical catalog
entry remains `coming-soon` until implementation and verification are complete.
After release, successful play updates the shared recent-game record.

## Accessibility

The board exposes its name and tile state to assistive technology. Score,
victory, and game-over changes use appropriate live announcements without
repeating every animation. Keyboard focus remains visible, controls have at
least 44×44px targets, and color is not the only way tile values or states are
communicated.

Touch gestures must distinguish horizontal from vertical intent and prevent
page scrolling only after the game gesture is recognized. Motion respects
`prefers-reduced-motion`; gameplay remains understandable when transitions are
disabled.

## Implementation status

Phases 6 and 7 are complete. The pure engine covers four-direction movement,
single-merge behavior, scoring, injected 2/4 tile spawning, first-win
detection, continuation, and game-over detection with deterministic tests. The
responsive bilingual interface supports arrow keys, WASD, and touch swipes,
with score panels, new game, win/continue, game-over, guidance, and FAQ.
Persistence, final site integration, and release audits have not started.
