# Tetris implementation plan

## Status

Product scope decisions are settled. Repository reconnaissance (step 1), the pure deterministic engine (step 2), deterministic engine coverage (step 3), versioned browser-local best-score storage (step 4), the responsive play screen (step 5), and the bilingual accessibility review (step 6) are complete. Work will proceed one phase at a time, returning for review before the next phase.

## Step 1 results

- Route: **/games/tetris**; game id: **tetris**.
- Route module: app/games/tetris/page.tsx; feature root: src/features/tetris/.
- Register the game in src/config/games.ts, the recent-game id validator in src/storage/recent-games.ts, and app/sitemap.ts.
- Keep the rules engine pure and deterministic. Keep browser storage in the feature storage adapter, using the shared safe-storage helpers.
- Put Tetris-specific Korean and English copy in src/i18n/tetris-content.ts and select it through useLanguage. Add shared UI labels to src/i18n/messages.ts only when appropriate.

## Confirmed scope

- Single-player marathon; play ends when blocks top out.
- Modern standard Tetris style, including T-Spins, combo, and back-to-back scoring.
- Level and gravity increase every 10 cleared lines.
- Keyboard and touch support; use on-screen buttons for touch.
- Save the best score locally in the browser. No online ranking.

## Implementation sequence

1. [Complete] Inspect route, catalog, localization, storage, and feature patterns; choose /games/tetris and game id tetris.
2. [Complete] Define the pure deterministic engine in `src/features/tetris/engine/`: board, seven-bag queue, collision, SRS rotation and kicks, movement, hold, ghost, lock delay, line clears, scoring, gravity, and top-out.
3. [Complete] Add deterministic unit coverage for seeded seven-bag behavior, SRS rotation and kicks, wall and floor collisions, line clears, hold restrictions, scoring bonuses, T-Spin qualification, gravity and lock delay, level transitions, and top-out.
4. [Complete] Add browser-only best-score persistence with versioned, validated storage and safe handling for malformed saved records, parse errors, and quota errors.
5. [Complete] Build the responsive play screen: board, score/level/lines, next and hold panels, start/pause/game-over states, keyboard support, and touch button controls.
6. [Complete] Review the Korean and English feature copy; verify keyboard operation, focus visibility, semantic labels, and 44px minimum touch targets.
7. Run the repository's test, lint, typecheck, and build commands; fix regressions and update `NEXT_TASK.md` when implementation is ready for the next handoff.

## Acceptance criteria

- Each piece can only lock in a legal position; full rows clear and rows above settle correctly.
- Piece generation, rotations, scoring, and gravity are deterministic under a supplied seed or fixed state.
- Hold can be used according to the selected modern ruleset, and the ghost piece matches the landing position.
- Level changes occur at each 10-line boundary and the configured gravity gets faster.
- T-Spin, combo, and back-to-back cases award their documented points.
- A top-out ends the run, shows the final score, and offers a restart.
- A new best score persists across reloads in the same browser; invalid data recovers safely.
- The game is playable by keyboard and touch in Korean and English layouts.

## Latest update — Tetris step 3: deterministic engine coverage (2026-09-23)

Added 12 deterministic tests for seven-bag generation, SRS kick tables, wall/floor collisions, row settling, hold limits, line and T-Spin scoring, combo and back-to-back behavior, level/gravity progression, lock delay, drop points, and top-out. The targeted command node --test tests/tetris-engine.test.mjs passed all 12 tests; npm test passed all 158 repository tests, npm run typecheck passed, and git diff --check reported no whitespace errors.

The tests exposed and fixed a T-Spin classification bug: a hard drop no longer qualifies by itself; a successful rotation remains eligible when immediately locked by hard drop. Best-score storage validation is deferred to phase 4 because its adapter is not implemented yet. The next phase is versioned browser-local best-score persistence.
