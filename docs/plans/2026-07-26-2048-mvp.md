# 2048 MVP Plan — 2026-07-26

## Context

Othello is complete through its local release-quality phase. The next game is
2048, implemented as a self-contained feature that reuses the existing catalog,
localization, recent-game, metadata, and safe browser-storage foundations.

## Product decisions

- Follow the original 2048 rules on a fixed 4×4 board.
- Start with two tiles. A successful move creates one new tile: 2 with 90%
  probability or 4 with 10% probability.
- Declare a win when a 2048 tile is first created and allow the player to
  continue afterward.
- End the game only when no valid move remains.
- Do not provide undo.
- Support arrow keys, WASD, and touch swipes.
- Autosave the current game and best score in the browser.
- Show only the current score and best score; do not add extended statistics.
- Keep accounts, remote features, leaderboards, and external services out of
  scope.

## Architecture decisions

- Place the implementation under `src/features/2048/`, separating the pure
  engine, React components, and storage adapters.
- Keep movement and merge rules deterministic. Inject tile placement and value
  selection so tests never depend on ambient randomness.
- Treat localStorage as untrusted input. Use versioned payloads, validate every
  field, and recover to a safe new game after parse, schema, or access failures.
- Keep route composition in `app/games/2048/page.tsx`; the route must not
  implement game rules.
- Put all player-visible copy in both Korean and English catalogs.

## Delivery sequence

1. **Specification and engine:** define domain types, movement transforms,
   merge and score behavior, tile spawning, win detection, continuation, and
   game-over detection.
2. **Play experience:** render the board and score panels; implement new game,
   keyboard controls, WASD controls, touch swipes, win/continue UI, and
   game-over UI.
3. **Persistence and integration:** add versioned current-game and best-score
   storage, resume automatically, register the route and sitemap, connect
   recent play, and add bilingual metadata and explanatory content.
4. **Release quality:** complete engine, storage, and interaction tests; audit
   responsive layout and accessibility; run the full verification suite before
   marking the catalog entry available.

## Acceptance criteria

- Every direction produces the exact original 2048 compression and merge
  result, and a tile can merge no more than once per move.
- Score increases by the value of each newly merged tile.
- Invalid moves neither change the board nor create a tile.
- Successful moves create exactly one 2 or 4 in an empty cell.
- The first 2048 tile presents a win state; choosing continue preserves the
  board and allows further play.
- A full board ends only when it has no horizontally or vertically adjacent
  equal tiles.
- Arrow keys, WASD, and touch swipes produce equivalent moves and do not scroll
  the page while operating the board.
- No undo control or undo persistence exists.
- Reloading restores a valid current game and best score. Invalid or
  unavailable storage never crashes the page.
- Korean and English content, keyboard focus, screen-reader status, touch
  targets, contrast, and reduced-motion behavior meet repository requirements.
